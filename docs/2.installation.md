title: Installation
description: Add the assistant to an AntelopeJS DMS project, give it the DMS builder tools, and open it in the dashboard.
mode: how-to
---

::steps
### Add the module

```bash [Terminal]
ajs project modules add @antelopejs/dms-assistant
```

The module brings its sidecar, Claude Code and the routes that connect a database. The README's compatibility table lists the `@antelopejs/interface-dms` range it needs. The dashboard renderer, `@antelopejs/dms-frontend`, must be in the range that `engines["@antelopejs/dms-frontend"]` of `frontend-vue/package.json` declares.

### Point the sidecar at the backend

In `antelope.config.ts`, set `backendUrl` to the origin the `api` module reserves:

```ts fragment [antelope.config.ts]
"dms-assistant": {
  source: { type: "package", package: "@antelopejs/dms-assistant" },
  config: {
    backendUrl: "${@api.API_LOCAL_BASE_URL}",
  },
},
```

### Give the chat the builder tools

The chat changes pages through the builder tools of the `dms` MCP server, which `@antelopejs/dms` serves in development. In the `dms` module's config, set `mcp.backendUrl` to `${@api.API_LOCAL_BASE_URL}`. Without it, Safe mode can change nothing. [Where the chat's tools come from](/docs/modules/assistant/configuration#where-the-chats-tools-come-from) explains why.

### Start the project in development mode

From the project folder, run the backend and the frontend in two terminals:

```bash [Terminal]
ajs project dev -w
```

```bash [Terminal]
ajs dms dev
```

The `-w` flag restarts the project when its `.env` changes, which the onboarding needs after it connects a database.

### Open the dashboard as an owner

Sign in as an owner. The onboarding window opens and connects the assistant to your Claude or Codex login. [Onboarding](/docs/modules/assistant/onboarding) covers that window.

To open the chat later, press `Ctrl` `Shift` `K` (`⌘` `⇧` `K` on macOS), or click the sparkle icon in the header.
::

A production frontend build shows no assistant, and with `NODE_ENV=production` the backend starts no sidecar.

## Run the backend without the sidecar

- To start the backend without the sidecar, set `DMS_ASSISTANT=0`.
- To stop the sidecar, stop the project. `Ctrl` `C` reaches the sidecar through the terminal's process group. On Linux, the AntelopeJS core also stops it on shutdown.
- A hot reload of the module keeps the sidecar running, unless the sidecar's build changed.
- If a crashed backend left its sidecar running, the next start stops that sidecar.
- The sidecar exits after 15 idle minutes. The next time the dashboard checks on it, the backend starts it again.
