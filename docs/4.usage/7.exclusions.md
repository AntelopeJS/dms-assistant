The Exclusions page (`/modules/ai/exclusions`) lists the data **Analyst** may never read. Only owners can open it. It applies to Analyst only: Builder runs in development, for owners, and is not filtered.

## What an exclusion covers

The list has one row per data route, with the fields excluded on it. An exclusion applies to every table that reads that route: excluding `email` on the customers route hides it on every page that lists customers. There is one list for the project, shared by every workspace.

When a field is excluded:

- Analyst never receives its values, in the rows it reads, the datasets it loads or what it computes from them.
- Analyst sees the column as redacted, so it can tell the user the column exists and is excluded.
- A filter or a sort on the field is refused.
- Free-text search is refused on any table reading a route with an exclusion, because a search could match the excluded field.

If the list cannot be read, Analyst reads no data until it can.

## Manage the list

Select **Add exclusion**, then pick a page and one of its tables. The table decides the data route. The dialog lists every column of every table you can see that reads that route, and you check the fields to exclude. If the route already has a row, the dialog opens it with its fields checked, and saving edits that row.

**Edit** on a row opens the same checklist. Unchecking every field removes the row, and so does **Remove**.

Each row shows the pages and tables its route covers. A row whose route no longer appears anywhere you can see is marked **Not found**. A field that no table shows any more stays checked in the dialog and is marked **Not found**. Neither is dropped: both stay enforced until you uncheck or remove them.
