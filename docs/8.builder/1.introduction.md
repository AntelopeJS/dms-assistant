The builder of `@antelopejs/dms-assistant` is the engine that changes a DMS project's pages, tables and data sources. It has no editor of its own. The [AI assistant](/docs/modules/assistant/introduction) calls it to change the project, and so does **Build it** in the DMS mockup Edit mode. Every change it makes is TypeScript in your sources, and the change compiles before it is written.

## What one change looks like

Once the builder is [installed](/docs/modules/assistant/builder/installation), ask the assistant to rename the **Revenue** card of a page to **Revenue invoiced**. The assistant calls the builder, which rewrites the card's `title` in the page's `PageController` file and typechecks the project. When the backend reloads, the page shows the new title. The source diff is ready to review before you commit it.

## How it works

The builder keeps no database of pages. It reads these structures from your sources:

| Structure | Source representation |
| --- | --- |
| Page | A `PageController` class |
| Block | One of the page's static fields or a `.child()` of another block |
| Table | A `Table`, a `DataController` and a model |

For each edit, the builder runs these steps:

1. It parses those files.
2. It applies the edit as an AST rewrite.
3. It typechecks the whole project in memory.
4. It writes the files only when the result compiles.

Hand-written code and builder-written code are the same code, so you can keep editing a page either way.

Clients reach the builder in two ways:

- modules in the same process, through the [`@antelopejs/interface-dms-builder`](https://github.com/AntelopeJS/dms-builder/tree/main/packages/interface-dms-builder/docs) interface. The assistant's agent tools use it through the assistant's backend.
- the DMS dashboard and other HTTP clients, through the HTTP API under `/api/builder`.

[Extending](/docs/modules/assistant/builder/extending) covers both.

::important
The builder rewrites source files, so by default it is on only in development (`ajs project dev`, with or without `-w`). A started build (`ajs project start`) has no builder routes unless [`builder.api.enabled`](/docs/modules/assistant/builder/configuration) forces them on.
::

## Who can use it

Every builder route requires an authenticated tenant owner.

## Connect an existing database

The builder can also wire a database you already run into the project, analyse its tables and map them into pages. Start from **Start from an existing database** in the assistant's onboarding popup, or ask the assistant to connect it. The `/api/builder/database` routes in [Extending](/docs/modules/assistant/builder/extending#database-routes) serve that flow.

## Works with the AI assistant

The assistant edits pages through the builder's operations. In **Safe mode**, its default, it changes the project only through the builder, so the builder typechecks every change and you can undo it.
