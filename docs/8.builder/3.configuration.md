The options live under `builder` in the `config` block of the module's entry in `antelope.config.ts`, which `ajs project modules add @antelopejs/dms-assistant` writes. `@antelopejs/dms-builder` read them at the top level of its own entry.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `builder.projectRoot` | `string` | the process working directory | The app's source root. A relative path resolves against the process working directory. Every module, table and page that connecting a database writes lands under it. |
| `builder.api.enabled` | `boolean` | the project's development mode | Mounts the `/api/builder/database` routes, or keeps them off. |

The builder that the DMS MCP server drives reads its own options under the `builder` key of the `dms` module. [Configuration](/docs/building/configuration) in the DMS docs lists them.

::note
The module does not read a `factoring` option. Remove it if an older configuration still holds one.
::

## When the routes are on

When `builder.api.enabled` is unset, the routes follow the core's development flag (`GetRuntimeInfo().dev`). The DMS reads the same flag for dev reload. The module does not read `NODE_ENV`.

| Command | Routes |
| --- | --- |
| `ajs project dev`, `ajs project dev -w` | On |
| `ajs project start`, which starts the project from its build | Off. The process mounts no `/api/builder/database` routes, so they answer `404`. |

`builder.api.enabled: true` mounts the routes on a started build. `builder.api.enabled: false` keeps them off in development.

::warning
With `builder.api.enabled: true` on a deployment, tenant owners can rewrite the deployed sources.
::
