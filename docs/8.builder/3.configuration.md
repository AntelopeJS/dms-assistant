title: Configuration
description: Every option of the builder module, and the commands that turn the builder on.
mode: reference
---

The options live under `builder` in the `config` block of the module's entry in `antelope.config.ts`, which `ajs project modules add @antelopejs/dms-assistant` writes. `@antelopejs/dms-builder` read them at the top level of its own entry.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `builder.projectRoot` | `string` | the process working directory | The app's source root, where page files live. A relative path resolves against the process working directory. Every page, table and query the builder writes lands under it. |
| `builder.api.enabled` | `boolean` | the project's development mode | Forces the builder on or off. |

::note
The module does not read a `factoring` option. Remove it if an older configuration still holds one.
::

## When the builder is on

When `builder.api.enabled` is unset, the builder follows the core's development flag (`GetRuntimeInfo().dev`). The DMS reads the same flag for dev reload. The builder does not read `NODE_ENV`.

| Command | Builder |
| --- | --- |
| `ajs project dev`, `ajs project dev -w` | On |
| `ajs project start`, which starts the project from its build | Off. The process mounts no `/api/builder` routes, so they answer `404`. Its frontend registration says the builder is off, so the page header shows no builder button. |

`builder.api.enabled: true` mounts the builder on a started build. `builder.api.enabled: false` keeps it off in development.

::warning
With `builder.api.enabled: true` on a deployment, tenant owners can rewrite the deployed sources.
::
